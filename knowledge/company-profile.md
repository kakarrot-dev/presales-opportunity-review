## 可引用条目结构

实际数据按下文的稳定条目 ID 维护。新增或更新条目时必须逐项填写稳定字段，不得以章节级更新时间或可信度代替条目级信息。

```yaml
company_profile:
  entries: []
company_profile_entry:
  id: null
  statement: null
  scope: null
  evidence: []
  updated_at: null
  owner: null
  confidence: null
  status: null
  review_due: null
```

- `id`：稳定且唯一的条目 ID；内容更新不得复用其他事实的 ID。
- `statement`：可引用的能力、边界、案例、工作量或商务基线陈述。
- `scope`：适用的产品、版本、行业、区域、交付方式及排除项。
- `evidence`：内部批准记录、验收材料或其他可核验依据的引用；不得写入客户文件正文。
- `updated_at`：条目最后核验日期，使用 `YYYY-MM-DD`。
- `owner`：对条目准确性和复核负责的角色或人员。
- `confidence`：仅使用 `high`、`medium` 或 `low`。
- `status`：仅使用 `verified`、`pending`、`retired`。
- `review_due`：最晚复核日期，使用 `YYYY-MM-DD`。

空白、未经核验或已过期的章节不得支持确定性结论；仅可作为待澄清信息，并明确其限制。公司基线缺失时，不得给出确定性的能力匹配、报价和参与建议；应先标记为待补充或待澄清。

- 不承诺未核验的产品功能、性能、安全、资质、交付周期、服务等级、案例和报价。

## L0-L3 判定基线

- `L0 直接满足`：必须有公司自有且可运行的现有能力、明确版本和适用范围，并具备演示、测试或验收证据。当前没有满足此门槛的产品条目。
- `L1 配置满足`：必须基于已验证的 L0 能力，只通过标准配置、参数或既有模板完成。当前没有可作为前提的 L0 产品条目。
- `L2 合作满足`：必须有已识别合作方、书面授权、供货或服务范围、成本、交付责任、验收责任和失效替代方案。西亚斯背景或口头合作线索本身不构成 L2。
- `L3 不建议承诺`：公司明确不具备，或资质、资金、责任、周期和关键依赖不可控的需求。
- `待内部确认`：当前默认状态。只要缺少有效条目 ID、条目为 `pending`、条目过期或证据不能覆盖需求粒度，就必须使用该状态。
