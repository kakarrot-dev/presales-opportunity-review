# 澄清问题规则

以完整的 `project-analysis.yaml` 为输入。未知、冲突、无法核验或影响决策的事项必须形成问题；不得用推测替代澄清。输出时必须拆分为彼此隔离的两套清单。

## 内部待确认清单

`03-clarification-internal.md` 仅供内部决策、能力和商务核验使用。每条记录必须包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `priority` | 优先级与阻塞程度 |
| `question` | 需要内部确认的具体问题 |
| `current_judgment` | 当前基于材料、能力基线和策略的判断 |
| `impact` | 对资格、方案、交付、报价或 Go/No-Go 的影响 |
| `owner` | 内部责任人或责任角色 |
| `deadline` | 决策或投标节点前的完成时间 |

内部问题可包含底价、能力边界、竞品判断、审批条件和策略推理，但这些内容不得自动迁移至甲方材料。

## 甲方正式澄清清单

`04-clarification-customer.md` 只包含适合正式提出、且不能由已提供材料或已核验证据解决的问题。每条记录必须包含以下字段：

| 字段 | 含义 |
| --- | --- |
| `topic` | 澄清主题 |
| `formal_question` | 面向甲方的中性、可答复的正式问题 |
| `reason` | 此问题与需求、范围、验收或合规的关系 |
| `response_format` | 期望答复形式，例如书面确认、清单或图纸 |
| `timing` | 以下四类标签之一 |

`timing` 只能使用以下标签：

- 投标前必须确认
- 中标后可以深化
- 不建议主动询问
- 建议由原厂及合作伙伴确认

正式提问不得透露内部立场、底价、能力弱项、竞品策略或未经验证的判断。对于“不建议主动询问”的事项，保留在清单中说明其处理方式，但不将其转化为对甲方的主动问题。
