# 评审与符合性分析规则

## 输入与记录

按 `procurement`、`packages`、原子需求、公司 L0-L3 匹配、三点估算和已核验 `evidence` 逐包分析。将结论分别写入 `bid.qualification_items`、`bid.compliance_items`、`bid.rejection_risks`；不得以未核验外部信息替代采购文件或公司基线。

## 资格与符合性路由

先进行**资格及符合性审查**，逐条记录来源、适用包件、截止时间、证明材料、当前状态和处置人：

- **硬性资格**：营业资质、许可、财务、业绩、人员、联合体或原厂授权等明示的准入条件。缺失或不能在截止前满足时列为 `bid.rejection_risks`，不能以一般风险提示替代。
- **废标风险**：签章、格式、保证金、报价口径、响应时限、实质偏离、禁止分包或其他可能导致否决的事项；区分文件明示规则与待澄清推断。
- **可补正的实质性问题**：仅在采购文件允许补正且不改变实质响应时记录补正路径、截止时间和责任人；未明示允许时不得假定可补正。
- **合作方依赖**：对 L2 合作满足项记录伙伴、授权/供货/交付边界、联合体或分包限制、替代方案和失效影响。
- **未知状态**：材料或证据不足、规则冲突或版本无法判断时，标记未知状态并说明需要的原件或澄清；不把未知写成符合。

## 评审机制路由

以最高优先级且可定位的采购规则为准，按实际机制选择下列路径；规则未明确时输出**未明确**并分析成交路径所缺信息：

- **最低价法**：核查通过资格及符合性后的比较范围、价格口径、异常低价、最高限价和并列规则；不得把技术优势转换为未规定的加分。
- **最高投入或最高报价排序**：核查有效报价或投入的排序方向、投入定义、上限/下限、可承受现金暴露和反向排序条件；不得默认最低价中标。
- **综合评分法**：提取资格门槛、价格、技术、商务、服务、业绩及扣分项的明示权重、公式和门槛，分别记录在 `bid.scoring_items`。
- **多轮谈判**：只根据文件明示的轮次、淘汰机制、可谈范围、最终报价和截止时间分析；不得假定谈判可改变资格、范围或实质条款。
- **主观方案评审**：记录评审维度、样品/演示、陈述、专家判断和证据要求，说明无法量化的主观性及应对证据。

## 得分估算边界

**只有存在明确分值时**才计算 `bid.estimated_score`，并列出每项公式、输入、证据和情景假设。分值、权重或公式不完整时仅做情景估算，或者保留 `estimated_score: null`；改为分析淘汰条件、排序规则和成交路径，不虚构精确得分。
